# 02-1 Grayscale 转 RGB

PNG 的 `Grayscale`（灰度，`Color Type = 0`）像素只有一个灰度分量。显示为 RGB 时，三个颜色通道取相同值：

$$
R = G = B
$$

关键在于：**根据 PNG 的 `bit depth`，把原始灰度 sample 映射到目标 RGB 位深。**

---

## 1. Grayscale 支持的 Bit Depth

对于 PNG `Color Type = 0`（Grayscale），合法的 bit depth 为：

| Bit Depth | 原始灰度范围 | 灰度级数 |
|---:|---:|---:|
| 1 | 0 ~ 1 | 2 |
| 2 | 0 ~ 3 | 4 |
| 4 | 0 ~ 15 | 16 |
| 8 | 0 ~ 255 | 256 |
| 16 | 0 ~ 65535 | 65536 |

其中：

- `0` 表示黑色；
- 最大值表示白色；
- 中间值按比例表示不同灰度。

---

## 2. 转换成 8-bit RGB 的通用公式

假设 PNG 的 bit depth 为 `b`，原始灰度 sample 为：

$$
g_{raw} \in [0, 2^b - 1]
$$

转换成标准 8-bit 灰度值：

$$
g_8 =
\operatorname{round}
\left(
g_{raw} \times \frac{255}{2^b - 1}
\right)
$$

然后：

$$
R = G = B = g_8
$$

流程可以表示为：

```text
raw grayscale sample
        │
        ▼
 scale to 0~255
        │
        ▼
       g8
      / | \
     /  |  \
    R   G   B

R = G = B = g8
```

---

## 3. Bit Depth = 1

1-bit grayscale 只有两个灰度值：

```text
0 → black
1 → white
```

对应关系：

| Raw | RGB |
|---:|---|
| 0 | `(0, 0, 0)` |
| 1 | `(255, 255, 255)` |

因为：

$$
g_8 = g_1 \times 255
$$

例如一个 scanline 中的数据：

```text
0 1 1 0 1 0 0 1
```

对应：

```text
black white white black white black black white
```

RGB 为：

```text
(0,0,0)
(255,255,255)
(255,255,255)
(0,0,0)
...
```

---

## 4. Bit Depth = 2

2-bit grayscale 每个像素有 4 种可能值：

```text
00 = 0
01 = 1
10 = 2
11 = 3
```

映射到 8-bit：

$$
g_8 = g_2 \times \frac{255}{3}
$$

得到：

| 2-bit | Raw | 8-bit Gray | RGB |
|---|---:|---:|---|
| `00` | 0 | 0 | `(0,0,0)` |
| `01` | 1 | 85 | `(85,85,85)` |
| `10` | 2 | 170 | `(170,170,170)` |
| `11` | 3 | 255 | `(255,255,255)` |

即：

```text
0 ───── 85 ───── 170 ───── 255
black                          white
```

---

## 5. Bit Depth = 4

4-bit grayscale 的范围为：

```text
0 ~ 15
```

映射到 8-bit：

$$
g_8 = g_4 \times \frac{255}{15}
$$

由于：

$$
\frac{255}{15} = 17
$$

因此：

$$
\boxed{g_8 = g_4 \times 17}
$$

例如：

| 4-bit | 8-bit | RGB |
|---:|---:|---|
| `0x0` | 0 | `(0,0,0)` |
| `0x1` | 17 | `(17,17,17)` |
| `0x2` | 34 | `(34,34,34)` |
| `0x3` | 51 | `(51,51,51)` |
| `0x4` | 68 | `(68,68,68)` |
| ... | ... | ... |
| `0x8` | 136 | `(136,136,136)` |
| ... | ... | ... |
| `0xF` | 255 | `(255,255,255)` |

这也可以理解为 **bit replication**：

```text
4 bit:

1010

扩展为 8 bit：

1010 1010
```

即：

```text
0xA → 0xAA = 170
```

等价于：

$$
g_8 = (g_4 << 4) | g_4
$$

---

## 6. Bit Depth = 8

8-bit grayscale 已经处于 `0~255` 范围，因此无需缩放：

$$
g_8 = g_{raw}
$$

例如：

```text
Gray = 0x00
→ RGB = (0,0,0)

Gray = 0x40
→ RGB = (64,64,64)

Gray = 0x80
→ RGB = (128,128,128)

Gray = 0xFF
→ RGB = (255,255,255)
```

代码形式：

```cpp
uint8_t gray = sample;

R = gray;
G = gray;
B = gray;
```

---

## 7. Bit Depth = 16

16-bit grayscale sample 范围为：

```text
0 ~ 65535
```

如果输出仍然使用 16-bit RGB，则直接：

$$
R_{16} = G_{16} = B_{16} = g_{16}
$$

例如：

```text
Gray = 0x1234

R = 0x1234
G = 0x1234
B = 0x1234
```

如果要转换成 8-bit RGB：

$$
g_8 =
\operatorname{round}
\left(
g_{16} \times \frac{255}{65535}
\right)
$$

由于：

$$
65535 = 255 \times 257
$$

所以可以写成：

$$
g_8 \approx \frac{g_{16}}{257}
$$

例如：

| Gray16 | Decimal | Gray8 |
|---|---:|---:|
| `0x0000` | 0 | 0 |
| `0x4040` | 16448 | 64 |
| `0x8080` | 32896 | 128 |
| `0xFFFF` | 65535 | 255 |

特别是：

```text
0x8080 → 0x80
0xFFFF → 0xFF
```

这可以理解成一个 8-bit 值扩展到 16-bit：

```text
8-bit:
10000000

16-bit:
10000000 10000000
```

---

## 8. 1/2/4 bit 并不是“一个像素占一个 byte”

对于低 bit-depth grayscale，多个像素会打包在同一个 byte 中。

### Bit Depth = 1

一个 byte 保存 8 个像素：

```text
10110010
││││││││
8 grayscale pixels
```

### Bit Depth = 2

一个 byte 保存 4 个像素：

```text
10 01 11 00
│  │  │  │
4 pixels
```

### Bit Depth = 4

一个 byte 保存 2 个像素：

```text
1010 0011
 │    │
pixel pixel
```

### Bit Depth = 8

一个 byte 保存 1 个像素：

```text
xxxxxxxx
   │
1 pixel
```

### Bit Depth = 16

两个 byte 保存 1 个像素：

```text
xxxxxxxx xxxxxxxx
      │
    1 pixel
```

PNG 的 16-bit sample 使用 **network byte order / big-endian**：

```text
0x1234

文件中：

12 34
↑  ↑
MSB LSB
```

## 9. Grayscale 解码到 RGB 的完整关系

对于 PNG Analyzer，可以将 **Raw Sample** 和 **Displayed RGB** 明确区分：

```text
PNG Color Type 0
Grayscale

Compressed Data
       │
       ▼
    DEFLATE
       │
       ▼
Filtered Scanline
       │
       ▼
    Defilter
       │
       ▼
 Packed Samples
       │
       ▼
Sample Unpacking
       │
       ▼
Raw Gray Sample
   b-bit value
       │
       │ normalize
       ▼
 Display Gray
    0 ~ 255
       │
       ├───────────┐
       │           │
       ▼           ▼
       R     G     B
       │     │     │
       └─same value┘
```

统一公式为：

$$
\boxed{
RGB =
\left(
S \frac{255}{2^b - 1},
S \frac{255}{2^b - 1},
S \frac{255}{2^b - 1}
\right)
}
$$

其中：

- `S`：原始 grayscale sample；
- `b`：PNG bit depth；
- 最终三个 RGB 通道取相同值。

---

## 10. 8-bit RGB 速查表

| PNG Bit Depth | 原始范围 | 转换到 8-bit |
|---:|---:|---|
| 1 | 0~1 | `gray × 255` |
| 2 | 0~3 | `gray × 85` |
| 4 | 0~15 | `gray × 17` |
| 8 | 0~255 | `gray` |
| 16 | 0~65535 | `gray / 257`（近似表达） |

最终均为：

$$
R = G = B
$$

## 11. Grayscale 与 tRNS

对于 `Color Type = 0`，PNG 仍然可以包含 `tRNS` chunk。

`tRNS` 可以指定一个特定的 grayscale sample 为完全透明。因此，如果最终输出 RGBA，不能简单地始终令：

```text
A = 255
```

而应比较当前 grayscale sample 是否等于 `tRNS` 中定义的透明灰度值：

```text
if gray_sample == transparent_gray:
    A = 0
else:
    A = max_alpha
```

因此，对于带 `tRNS` 的 grayscale PNG，最终可理解为：

```text
Gray Sample
    │
    ├──→ R = Gray
    ├──→ G = Gray
    ├──→ B = Gray
    │
    └──→ compare with tRNS
              │
              ├── equal     → A = 0
              └── not equal → A = maximum
```
